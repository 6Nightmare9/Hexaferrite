## 1. Кратко о проекте и главном принципе

**Объект.** W-гексаферриты основной серии SrFe(18-x)A(x)O27, где A = Co, Zn, Mn. Базовая сетка составов x = 0,5; 1; 1,5; 2.
Проект также принимает фактически полученные составы, промежуточные x и смешанное легирование.

**Цель.** Построить воспроизводимую теоретическую модель, которая по составу и заданным условиям:

- предлагает допустимые структуры и распределения катионов по позициям;
- считает магнитные состояния, обмен, анизотропию, собственные резонансные моды;
- строит спектры ФМР (ферромагнитного резонанса) и зависимости от поля, угла, температуры;
- прогнозирует электромагнитные свойства (магнитная проницаемость и т. п.);
- независимо разбирает ваши РФА, мёссбауэровские спектры, РЭМ/EDS;
- сравнивает прогноз с экспериментом с честной неопределённостью.

Целевой критерий: ошибка не более 10 % для заранее перечисленных величин в подтверждённой области. Это критерий проверки,
а не обещание: достигнут ли он, покажет сравнение с независимыми данными.

**Главный принцип.**

> литература и расчёты (DFT) -> **фиксация** модели и прогнозов -> проверка на лабораторных данных

Параметры берутся из опубликованных статей и из физических расчётов. Ваши лабораторные измерения по умолчанию служат
только для проверки. Модель сначала «замораживается» вместе с прогнозами, и лишь затем сравнивается с экспериментом.

Зачем так. Если подгонять параметры под те же данные, на которых потом «проверяют», совпадение ничего не доказывает.
Поэтому в проекте техническими средствами (а не только договорённостью) разделены:

- «теоретическая сторона» (литература, расчёты, код модели);
- «слепая сторона» (лабораторные данные и резерв литературы для проверки).

Калибровка по вашим данным возможна, но только по явной команде; при этом создаётся новая версия модели, а откалиброванные
данные перестают быть независимой проверкой.

Режимы работы (по ТЗ):

| Режим | Что это |
|---|---|
| Основной прогноз | Только литература, DFT и физика. Вход: заранее оговорённый состав, температура, поле, ориентация, геометрия. |
| Независимая проверка | Модель и прогнозы зафиксированы до просмотра ответов; потом сравнение. |
| Прогноз с экспериментальными входами | Можно подставить измеренные фазовые доли или заселённости; результат маркируется отдельно и не выдаётся за прогноз «по формуле». |
| Калибровка | Только по явной команде, с новой версией модели и проверкой на других образцах. |

## 4. Методы

### 4.1. Аудит и контрольные суммы

Для каждого файла архива записана контрольная сумма SHA-256. Команда `audit` проверяет:

- совпадение хэшей файлов с манифестами и с содержимым исходного архива;
- наличие дубликатов (вложенный архив-дубликат учитывается, но как независимое измерение не считается);
- что защищённые зоны действительно помечены «только чтение»;
- согласованность реестра (образцы, измерения, раскрытие прежнего использования);
- работу защиты от утечек (самопроверки, см. 4.2) и целостность файлов реестра (`SHA256SUMS`, состояние git).

Аудит по умолчанию ничего не пишет. С ключом `--write-manifest` он сохраняет отчёт запуска (хэши, версии git, окружение)
в `registry\runs\`.

### 4.2. Изоляция лабораторных данных

Цель — остановить **случайную** утечку лабораторных данных в код теории. Это защита от собственных ошибок, а не песочница
против злонамеренного кода.

- Реализация: при `import hexw` в Python устанавливается аудит-хук (перехватчик открытия файлов и других операций).
  Он пускает в защищённые папки только модули из белого списка: `experiment`, `validate`, `audit`, `ingest`, `io`.
  Модули теории (`theory`, `params`, `dft`, `structures`, `spin`, `util` и любые новые) получают отказ.
- Закрыты обходные пути: открытие файлов разными способами, чтение каталогов, копирование (включая `copy2` в Windows),
  базы SQLite, пути UNC и вида `\\?\`, junction и символические ссылки, короткие имена 8.3, регистр букв, запуск подпроцессов
  и `multiprocessing` (дочерним процессам передаётся тот же защитный режим). Запись в `raw\` и `vault\` запрещена всем.
- С 26.10.2026 в защищённую зону входит и **литературный резерв** (`literature_holdout\` и исходники holdout-статей;
  список в `project\config\holdout_sources.json`): теория его читать не может; читать может только модуль проверки
  после фиксации модели и аудит.
- Проверено независимо двумя раундами (тестировщик и ревьюер). Накладные расходы — около 48 мкс на открытие файла.
- **Не перехватывается:** вызовы через `ctypes`/WinAPI напрямую; внешние программы и дочерние процессы, не импортирующие `hexw`
  (например, сам `pw.x` — проверяется лишь командная строка при запуске); метаданные файлов (имена, размеры, даты).
  Подробности — `project\docs\ISOLATION.md`.

### 4.3. Реестр и версии

- Каталог `registry\` — под git. Ключевые файлы только для чтения; генераторы не перезаписывают готовые файлы
  без явного `--force` и чистого git.
- Для параметров хранится роль источника (`source_role`): `literature_fit`, `literature_holdout`, `dft`,
  `laboratory_validation`, `legacy_prediction`, `explicit_calibration`.
- Для прогноза сохраняется список его входов, для проверки — список проверяемых ответов. **Пересечение входов прогноза
  и проверяемых ответов — ошибка**, а не предупреждение.
- Версия модели определяется хэшем набора параметров: любое изменение даёт новую версию. Старые результаты проверки
  не удаляются — хранилище результатов только дописывается.
- Режим проверки (`retrospective` или `independent_candidate`) берётся из `prior_use.yaml`. Независимой считается лишь проверка
  по измерению, для которого найдено «нет прежнего использования» **и** есть ваше подтверждение. Сейчас таких нет.

### 4.4. Литературный поиск и извлечение

- Источники поиска перечислены в `lit_search\SEARCH_LOG.md` вместе со всеми запросами, временем и инцидентами
  (например, отказы API по лимиту). Платные статьи не обходились, Sci-Hub и подобное не использовались.
- Релевантность кандидатов в `candidates.csv` — эвристика по заголовку и реферату: 1 — Sr W-тип; 2 — прочие W-типы со свойствами
  и историческая литература; 3 — прочее по W-типу; 4 — методологические аналоги (M-тип, ФМР, мёссбауэр). Оценка не заменяет чтения.
- Каждое значение сохраняется с DOI, локатором (таблица/рисунок/страница), дословной строкой, составом, условиями синтеза и
  измерения, методом, единицами, статусом (измерено / рассчитано / оцифровано / принято авторами / выведено нами).
- Противоречия не усредняются: альтернативы остаются отдельными записями (`literature\fit\CONFLICTS.md`).

### 4.5. Правила происхождения чисел

1. Ни одно число не «вспоминается по памяти» и не восстанавливается из неподтверждённых фрагментов; недоступный текст
   отмечается как недоступный.
2. Приоритет переносимости: (1) прямо Sr–Co/Zn/Mn W-серии; (2) близкие Sr W-составы; (3) другие W-системы, включая Ba — с
   обоснованием и расширенной неопределённостью; (4) другие типы гексаферритов — только как методологические аналоги.
3. Числа из M-, Y-, Z-фаз в W-фазу и из Ba-систем в Sr-системы переносятся только с обоснованием и добавочной неопределённостью.
4. Таблица, рисунок и CIF одного измерения (и повторно процитированные значения) — одно измерение, а не независимые подтверждения.
5. Литературные DFT-результаты (например, Islam) — это внешний расчётный prior, а не наши DFT; метка `dft` зарезервирована
   под наши собственные расчёты.
6. Число свободных параметров должно соответствовать объёму данных: для малого корпуса проект не изображает универсальный предсказатель.

### 4.6. Разбиение fit / holdout

Разбиение сделано по публикациям и химическим сериям, а не по точкам. Решение руководителя — «вариант A с правкой»
(файл `literature\SPLIT_DECISION.md`, 25.10.2026).

| Часть | Что входит |
|---|---|
| **fit** (подгонка параметров) | L02 (серия SrCo2-xZnxW с магнитной структурой); L01 только образцы Mg и Ni; L05 (литературный DFT как prior); L03 и C004 (стехиометрия, пределы синтеза); L11 (BaMn2W и др. BaMe2W) — как источник **переноса Ba -> Sr** (правка). |
| **holdout** (слепой резерв) | L01 образцы Co и Zn (тип `same_group_reproducibility`); C023, C015 (независимая Sr-группа); Ba-работы и композиты (L12, C057, C060, C044, C056, C036, C052, C066), проверяющие допущение переноса Ba -> Sr. C056 — независимая проверка Mn-ветки. |
| Исключено | 8 вторичных цитат и 1 запись низкого качества. |
| Только методология | C112, C115 (конвенции DFT/J; числа не переносятся). |

Почему так:

- Mn в Sr-W в корпусе нет вообще. L11 — единственный источник по Mn в W-фазе; без него параметризация Mn шла бы только по DFT.
  Поэтому L11 отдан в fit как перенос Ba -> Sr (с расширенной неопределённостью), а независимой проверкой Mn служит C056 из другой группы авторов.
- L01 Co/Zn повторяет составы L02 той же группой авторов: это проверка «между партиями», **она оптимистична** и не заменяет независимую.
- Независимых Sr Co/Zn данных в корпусе почти нет (C023 — одна температура; C015 — композит), поэтому holdout слабый. Это зафиксировано, а не скрыто.
- Блокируются публикации целиком: PDF статьи L01 содержит и fit-, и holdout-данные, поэтому вся L01 закрыта для теории; её fit-часть (Mg, Ni) доступна только через `literature\fit`.
- Скрипт разбиения сравнивает числовые маркеры holdout-записей с текстом fit-файлов и останавливается при совпадении.

Содержимое `literature_holdout\` в руководстве не раскрывается: это слепой резерв. Файлы с исходными смешанными записями
перенесены внутрь резерва.

### 4.7. План DFT

Движок: Quantum ESPRESSO 7.6 (последовательная сборка с OpenMP, **без MPI**), метод DFT+U (по Дударёву), спин-поляризованный,
псевдопотенциалы SSSP 1.3 (в том числе GBRV для Fe, O, Sr, Co, Zn, Mn). Пробное значение U для Fe — 4 эВ. Ноутбук: Ryzen 7 7735H, 15,2 ГБ ОЗУ, Windows 11 без прав администратора.

Измерения пилотов (на один шаг SCF-итерации и пик памяти):

| Пилот | Система | Время на итерацию | Память |
|---|---|---|---|
| a | Fe2O3, 10 атомов, антиферромагнитный | 6–12 с | 0,2 ГБ |
| b | SrFe12O19 (M-тип), 64 атома | 79 с | 1,9 ГБ |
| c | W-тип SrFe18O27, 92 атома | около 290 с (растёт в первых итерациях; расчёт не сошёлся за 3 итерации) | 3,3 ГБ |

Параллелизм: многопоточность в этой сборке только замедляет, поэтому 1 поток на процесс; ускорение дают только
независимые запуски. Для W-типа ограничение — память, не более 3 процессов одновременно.

Что посильно на ноутбуке:

- коллинеарные магнитные конфигурации для оценки обменных интегралов J: около 17–20 часов на состав (~14 конфигураций, по ~3,5 ч CPU, на трёх процессах);
- калибровка U и методики на гематите и M-типе (M-тип в 3–4 раза быстрее);
- локальные моменты и знаки главных J.

Что не посильно (берётся из литературы): анизотропия со спин-орбитальным взаимодействием (SOC) со сходимостью по k, релаксация 92-атомной ячейки,
суперъячейки, десятки составов. Γ-только на такой ячейке даёт систематическую погрешность; нужна проверка сеткой 2x2x1 на 2–3 конфигурациях.
Времена кампании — **оценка**, измерена только итерация. WSL2 с настоящим MPI дал бы выигрыш, но решено его не ставить.

Приоритет кампании обменов — составы с Mn (по ним нет литературы для Sr).

### 4.8. Физика магнитной модели

Подробности и все оговорки — `project\docs\MAGNET_MODEL.md`. Ядро описывает образец как **макроспин** (один вектор намагниченности m
на зерно). Параметров материала в коде нет: Ms, K1...K4, размагничивающий тензор, затухание α и γ задаёт вызывающий.
Тесты используют только помеченные SYNTHETIC значения.

**Единицы и конвенции**

- Система SI. Поле в программном интерфейсе — **μ0H_ext** в теслах, то есть приложенное внешнее поле, а не индукция внутри образца.
- Ось z направлена вдоль оси c кристалла, угол θ отсчитывается **от оси c**, φ — азимут в базисной плоскости.
- γ и γ/2π — разные величины: γ в рад/(с·Тл), γ/2π в Гц/Тл (для g = 2 около 27,99 ГГц/Тл). Задаётся ровно одним способом (g, или γ/2π, или γ); значения по умолчанию нет.
- Временная конвенция **exp(−iωt)**, восприимчивость χ = χ′ + iχ″; потери соответствуют χ″ > 0 при ω > 0.
- Восприимчивость по умолчанию **внешняя** (динамическое размагничивание учтено через тензор N); внутренняя восприимчивость доступна отдельно с пересчётом.

**Свободная энергия** (на единицу объёма, Дж/м³):

F(m) = K1 sin²θ + K2 sin⁴θ + K3 sin⁶θ + K4 sin⁶θ cos6φ − Ms (B·m) + (μ0 Ms² / 2) m·N·m

Первые члены — магнитокристаллическая анизотропия (одноосная и базисная шестого порядка), далее — зеемановская энергия во внешнем
поле и энергия размагничивания формы (форма учитывается только через N, чтобы не считать её дважды). Для c-состояния поле анизотропии
μ0H_A = 2(K1 + 2K2 + 3K3)/Ms; для диска, плоскость которого перпендикулярна c, эффективное поле уменьшается на μ0Ms.

**Равновесные состояния.** Ищутся **все** локальные минимумы энергии (сетка точек на сфере плюс симметричные затравки, затем уточнение методом Ньютона),
проверяется устойчивость по гессиану. Различаются классы: осевое, плоскостное, конус (при H = 0), наклонённое полем. Метастабильные состояния сохраняются
с разностью энергий. Гистерезис строится прослеживанием ветви от предыдущего состояния.

**ФМР.** Два метода, совпадающие на машинной точности:

- линеаризованное уравнение Ландау–Лифшица–Гильберта (LLG): частота ω = (γ/Ms)·√det(Hs), где Hs — гессиан энергии на касательной плоскости; это основной метод;
- Смит–Бельерс: ω = γ / (Ms sinθ) · √(F_θθ F_φφ − F_θφ²); особенность на полюсе sinθ → 0 обходится сменой полюса, без молчаливой регуляризации.

Для однородной прецессии в предельных случаях получаются формулы Киттеля (сфера, эллипсоид, плёнка), что используется как тест.
Для состояния «конус» нулевая мода сообщается как `neutral_zero_mode` (у макроспина там нет конечной частоты).
`H_res` — резонансное поле при заданной частоте и направлении поля — ищется прямым сканированием с отслеживанием ветвей; результат
имеет статус `ok` или `no_resonance_in_range`, края диапазона никогда не подставляются как «корни».

**Восприимчивость χ(f, H).** Решается линейное уравнение LLG; тензор имеет ранг 2 (вдоль m0 отклика нет), проверяются пассивность
(антиэрмитова часть положительна) и соотношения Крамерса–Кронига (достигнутая точность в тесте — порядка 4·10⁻⁴ при допуске 2 %).
Проницаемость μ_r = I + χ_ext.

**Поликристалл.** Ансамбль **невзаимодействующих зёрен** со случайной или текстурированной (Марч–Доллас) ориентацией оси c; каждое зерно получает тот же
размагничивающий тензор образца (упрощение). Состояние зерна: глобальный минимум или состояние, прослеженное от направления поля. Межзёренное взаимодействие и пористость
**не реализованы** и возвращают статус `not_implemented`, а не число.

**Неопределённость.** Монте-Карло: параметры берутся из заданных распределений, итог — медиана и интервал (по умолчанию 2,5–97,5 %) по валидным выборкам;
сбои учитываются отдельным счётчиком и не заменяются.

**Проверенность.** В ядре 76 тестов на аналитических пределах (по данным руководителя; в тестовых файлах я насчитал 60 функций `test_*`, различие
объясняется параметризованными тестами — сам набор я не запускал).

### 4.9. Статусы ширины линии

Ширина считается по спектру (по частоте или полю). Разведены три разные «позиции линии»: собственная мода из модели, максимум спектра и середина интервала полувысоты.
Статус ширины (FWHM):

| Статус | Смысл |
|---|---|
| `valid` | линия целиком в окне, пик один, в интервале полувысоты достаточно точек (не меньше 5); ширина определена |
| `left_censored` / `right_censored` / `both_censored` | линия обрезана краем окна слева, справа или с обеих сторон; край окна как значение не подставляется; окно можно расширить в пределах разрешённого |
| `multipeak` | есть другой заметный пик (выступает не менее 10 %) с высотой не ниже полувысоты главного |
| `insufficient_resolution` | слишком мало точек для надёжной ширины; даётся лишь оценка `width_estimate` |
| `no_peak` | пика нет |

Приоритет при нескольких причинах: обрезание, затем multipeak, затем разрешение, затем valid. Пересчёт ширины из частоты в поле
(Δ(μ0H) = Δf / |df/dB|) допустим только на участке с примерно постоянным наклоном ветви; при нулевом наклоне даётся статус `slope_zero`.
Связь FWHM = √3·ΔH_pp (между экстремумами производной) верна только для лоренциана.

## 5. Ограничения и честные оговорки

**Проверка ретроспективная.** Все 13 лабораторных измерений уже использовались: РФА — в прежних анализах (Umnik), мёссбауэр — в прежней модели
(по вашему подтверждению). Согласие или расхождение с ними не будет слепым тестом. Независимая проверка опирается на литературный резерв
(holdout). Настоящую слепую проверку даст только новая, нетронутая серия образцов.

**Резерв литературы слаб.** L01 Co/Zn — та же группа авторов, что и в fit (оценка оптимистична); независимых Sr Co/Zn данных мало (одна температура, один композит);
Ba-данные проверяют допущение переноса Ba -> Sr, а не саму модель, и успех для Ba не доказывает перенос для Mn.

**Главные пробелы литературы (по карте покрытия и решению о разбиении):**

- нет данных по системе Sr–Mn–W;
- нет экспериментальных констант анизотропии K1, K2 для Sr W-типа;
- нет параметра затухания α, g-фактора и ширин линий ФМР;
- нет промежуточных составов x = 0,5–1,5.

Они закрываются DFT, где возможно (обмен), либо остаются диапазонами неопределённости. Ничего не «дорисовывается».

**Платные статьи не получены**, включая работу по DFT обменов для SrFe18O27 (Islam 2024) и старую работу по ФМР Zn2-xCoxW.

**DFT на ноутбуке ограничен.** Нет MPI, один поток на процесс. SOC-анизотропия и релаксация не посильны, их берут из литературы. Времена кампании — оценки. Γ-только расчёт даёт систематическую погрешность.

**Изоляция не абсолютна.** Это защита от случайной утечки (хук Python), а не песочница. Вызовы через ctypes/WinAPI и внешние программы без пакета `hexw` не перехватываются.

**Магнитная модель — макроспин:** одна однородная мода на состояние; нет доменов, спин-волновых мод, температурных зависимостей параметров, базисной анизотропии высших порядков;
затухание только по Гильберту и не зависит от частоты; поиск минимумов эвристический (очень узкие минимумы могут быть пропущены); ядро на независимом ревью.

**Метаданные образцов предварительны:** состав — по именам файлов; прекурсор Mn для SMP-001...004 неизвестен; определение x относительно прекурсора не подтверждено; порядок стадий отжига SMP-001...004 — допущение.

**Не создано результатов анализа ваших РФА и мёссбауэра.** Любые числа о ваших образцах в этом руководстве отсутствуют намеренно.

Также желательно: подтвердить предварительные метаданные образцов (состав, даты, атмосфера, охлаждение, плотность) вместо «из имён файлов».
