# Как работать с HexW

Рабочая версия 0.2. Инструкция от 27 октября 2026 г.

Все части проекта находятся в **C:\MIPT\working_stuff\Hexx**. Исходная флешка для работы не нужна.

## Что это за программа

HexW — локальная исследовательская программа для W-гексаферритов семейства **SrFe₁₈₋ₓAₓO₂₇**, где A = Co, Zn, Mn, Mg, Ni, суммарно 0 ≤ x ≤ 2. Примеры: SrCoZnFe₁₆O₂₇, SrMn₂Fe₁₆O₂₇, SrMgFe₁₇O₂₇. Возможность ввести смесь ещё не означает, что она экспериментально проверена.

Литературные данные, физические уравнения и явно обозначенные гипотезы задают параметры модели. По составу и условиям программа считает структурные кандидаты, магнитное равновесие, собственные частоты однородного магнитного режима, спектры отклика, намагниченность, анизотропию и магнитную проницаемость. Неопределённые параметры рассчитываются ансамблем сценариев.

Это не обученная универсальная нейросеть, которая знает все свойства вещества по формуле. Текущий интерфейс не читает новые статьи автоматически и не улучшает модель от самого факта загрузки эксперимента. Добавление источников и развитие физической модели — отдельная работа агента и исследователя с новой версией и проверкой. Собственные измерения используются для анализа и сопоставления с зафиксированным прогнозом.

Для обычного расчёта не нужно открывать этот чат или оплачивать отдельные обращения к ИИ. После установки окружения расчёты выполняются средствами Python на ноутбуке. Интернет нужен для исследования новой литературы и обновления окружения, а не для каждой точки готовой модели.

**Независимая точность ФМР ≤10% пока не установлена.** Полное ТЗ A+B ещё не закрыто; перечень реализованных и незавершённых блоков находится в [итоговой сводке](../MODEL_STATUS_V02_RU.md).

## Запуск и остановка

1. Откройте папку C:\MIPT\working_stuff\Hexx.
2. Дважды нажмите **START_HEXW.cmd**. Если сервер уже запущен помощником или вами, вторую копию запускать не нужно.
3. Откройте в браузере **http://127.0.0.1:8765/**. Это адрес программы на вашем ноутбуке; он не публикует проект в интернете. После остановки сервера или выключения ноутбука страница не работает.
4. Оставьте окно сервера открытым. Для остановки обычного ручного запуска нажмите в нём Ctrl+C и дождитесь завершения текущей задачи. Закрытие браузерной вкладки само по себе расчёты не останавливает.

Численные библиотеки ограничены двумя потоками; интерфейс выполняет одну задачу за раз. Не запускайте одновременно много экземпляров программы. Нагрузка зависит от числа сценариев, температур, полей и частот. Для первых опытов оставьте 48 сценариев и 3–5 полей. Длинные расчёты выполняйте при питании ноутбука от сети.

При изменении кода помощником сервер нужно перезапустить и обновить вкладку. Один сервер может обслуживать несколько вкладок; у них общая очередь задач.

## Первый расчёт: SrCoZnFe₁₆O₂₇

1. Откройте вкладку **«Расчёт»**.
2. Нажмите **«Заполнить пример Co–Zn»**. Кнопка только заполняет форму.
3. Проверьте значения:

| Поле формы | Значение | Смысл |
|---|---|---|
| Формула | SrCo1Zn1Fe16O27 | SrCoZnFe₁₆O₂₇, один Co и один Zn на формульную единицу |
| Температура | 300 K | Температура прогноза |
| Поле: начало / конец / точек | 0 / 0.8 / 3 | Три внешних поля: 0, 0.4, 0.8 Тл |
| Направление θ / азимут φ | 0° / 0° | Поле вдоль кристаллографической оси c |
| Частота: от / до / точек | 0.1 / 100 / 401 | Сетка спектра в ГГц |
| Форма | Сфера | Явно выбранная идеальная геометрия материала |
| g | 2 | Сценарный g-фактор |
| α | 0.02 | Сценарное демпфирование Гильберта |
| Число реализаций | 48 | Число наборов неопределённых параметров |
| Название | Первый расчёт Co–Zn | Подпись в списке результатов |

4. Нажмите **«Рассчитать» один раз**. В блоке «Задачи» следите за состояниями «В очереди», «Выполняется», «Готово».
5. Нажмите **«Открыть результат»**. Повторно результат доступен во вкладке **«Результаты»**.

Для этого примера дополнительно сохранён файл настроек `project/config/cozn_first_example.yaml`. Он задаёт те же физические условия и сетки, что кнопка в интерфейсе. У предыдущей демонстрационной серии сетка поля была другой: 0, 0.3, 0.8 Тл; это отдельные сохранённые расчёты.

g = 2, α = 0.02 и сферическая форма — условия учебного примера. Не переносите их автоматически на реальный поликристаллический образец. Текстура, геометрия, пористость, многодоменность и ориентация должны соответствовать постановке реальной задачи.

## Как читать результат

**Таблица частот.** Для каждой пары «температура–поле» указаны медиана низшей недемпфированной собственной частоты основного состояния, 95% диапазон сценариев и число допустимых реализаций. Это не автоматически частота максимума поглощения. Если много реализаций не дали допустимого результата, вывод условен; увеличение их числа не исправляет физическую модель.

**График зависимости от поля.** Линия — медиана, полоса — разброс сценариев. Полоса не является подтверждённой экспериментальной погрешностью.

**Спектры.** Показан средний условный отклик χ относительно внешнего поля. Из-за неопределённых параметров и конечного ансамбля на нём могут быть мелкие пики. Они сами по себе не доказывают разные обменные моды или собственное неоднородное уширение реального вещества.

**Магнитные параметры.** Mₛ — намагниченность насыщения; T꜀ — температура Кюри; K₁…K₄ — коэффициенты анизотропии. У каждого параметра есть физические предпосылки и интервал сценариев. χ относительно внешнего поля и μ относительно внутреннего поля сохраняются отдельно.

**Файлы** доступны в раскрывающемся блоке результата:

| Файл | Для чего использовать |
|---|---|
| fmr_vs_field.png / .csv | Рисунок и таблица собственной частоты от поля |
| fmr_spectra.png | Обзор спектров для разных полей |
| T000_H0000_spectrum.csv и аналогичные | Частотные таблицы χ/μ для конкретных температуры и поля |
| request.json | Все фактически использованные входные условия |
| summary.json | Сводка частот и параметров |
| material.json | Источники параметров, применимость и предположения |
| structural_hypotheses.json; candidate_…_template.cif | Кандидаты заселённостей и геометрия на литературном шаблоне |
| parameters.npz; T…_H….npz | Машиночитаемые массивы сценариев и отклика |
| checkpoint.json | Состояние и контрольные суммы расчёта |
| freeze.json | Проверяемая фиксация завершённого прогноза, если вы её выполнили |

CSV открываются в Excel. Если колонки не разделились, используйте «Данные → Из текста/CSV» и разделитель запятую. Параметры указаны в названиях колонок; частотные спектры — в ГГц, некоторые внутренние величины — в Гц. Проверяйте единицы перед сравнением.

CIF-кандидаты не являются результатами полной релаксации атомов конкретного состава и не служат готовыми атомными входами DFT. Текущий прогноз по формуле описывает однородный магнитный режим. Отдельный многоподрешёточный решатель требует явно заданных обменных параметров.

## Четыре рабочих вкладки и справка

**«Расчёт»** — теоретический прогноз для состава и условий. Для температурного ряда или произвольного списка полей используйте файл настроек; обычная форма задаёт одну температуру и равномерную сетку поля.

**«Анализ данных»** — отдельная обработка исходного измерения. Укажите полный путь к существующему файлу на ноутбуке. Это не загрузка файла в облако. Пример записи пути: C:\MIPT\working_stuff\Hexx\vault\lab_validation\… . Исходные файлы сохраняются; результаты пишутся отдельно.

**«Проверка модели»** — сначала выберите и зафиксируйте завершённый прогноз, затем сравнивайте его с заполненным файлом целей. Фиксация связывает код, литературу, настройки и результаты контрольными суммами. Она не означает, что модель признана точной.

**«Результаты»** — текущие прогнозы и обработанные измерения. Архивные прогнозы скрыты по умолчанию; включите флажок для просмотра прежних версий. Архив не удаляется. «Текущая» означает соответствие текущему коду и литературному корпусу, а не экспериментальное подтверждение.

**«Как работать»** — краткая встроенная инструкция.

## Анализ измерений: что подготовить

Перед доступом к измерениям требуется зафиксированный теоретический прогноз.

| Метод | Что передать и указать | Что сейчас выдаётся |
|---|---|---|
| РФА | MDI или таблица 2θ/интенсивность, длина волны; при наличии — инструментальная ширина и CIF | Пики, d-расстояния; оценка Шеррера при допустимых исходных данных; первичная проверка картины по фиксированному CIF |
| Мёссбауэр | SPC или таблица скорость/счёт; подтверждённая калибровка α-Fe | Без калибровки — график по каналам. После калибровки — альтернативные секстеты и параметры в приближении тонкого поглотителя |
| РЭМ | Изображение, масштаб мкм/пиксель, область без надписей и линейки; при необходимости исправленная маска | 2D статистика выделенных объектов, маска и наложение для проверки |
| EDS | Уже количественно обработанный CSV: element, weight_percent, необязательно std_weight_percent | Атомные отношения и распространение заданных ошибок |
| ФМР | Таблица ось/сигнал, единицы оси, поглощение или измеренная производная, фон | Первичные характеристики пиков с проверкой обрезания и разрешения |

Полный количественный Ритвельд пока не реализован. Размер объектов на РЭМ не равен размеру когерентных областей РФА. Секстеты не назначаются автоматически узлам решётки. EDS не определяет валентность и заселённости узлов. Ширина производной ФМР не равна FWHM поглощения.

## Как сравнивать теорию и эксперимент

1. Задайте и сохраните теоретический прогноз с нужными условиями.
2. Во вкладке «Проверка модели» выберите его и нажмите «Зафиксировать этот прогноз».
3. Обработайте измерения отдельно. Убедитесь в калибровке, единицах и определении извлекаемой величины.
4. Возьмите шаблон `project/config/validation_targets_example.json`, создайте его рабочую копию с реальными измерениями и понятным происхождением, заполните все необходимые условия и ошибки. Установите `template_only=false`. Не подставляйте прогноз в поле измеренного ответа. Пока шаблон содержит заполнители, сравнение блокируется.
5. Укажите полный путь к заполненной копии в форме сравнения. Предпочтительно хранить новые рабочие измерения и копии целей в отдельной папке внутри проекта, например `runs/user_inputs/`; сохранённый исходный архив не меняйте.
6. Просмотрите отчёт. PASS относится к одной явно сопоставленной величине и выбранному критерию. Неопределённый, несопоставимый или недостаточно разрешённый результат может получить статус «не оценено».

Прежнее использование данных сохраняется в статусе проверки. Имеющиеся сравнения с литературой являются ретроспективными, с раскрытием прежнего доступа разработчика; полностью слепой проверкой их называть нельзя. Автоматической подгонки параметров после анализа измерения нет.

## Прерывания, резервная копия и частые затруднения

Расчёт сохраняется после подготовки параметров и после каждой пары «температура–поле». После сбоя запустите сервер и нажмите «Возобновить» у текущего прерванного расчёта. Незавершённая точка выполняется заново. При изменении кода/корпуса создавайте новую версию; архивный результат не нужно вручную «чинить».

Для резервной копии остановите вычисления и скопируйте всю папку Hexx на выбранный вами носитель. Git хранит версии кода и части корпусов, но не заменяет копию всех исходных измерений и результатов. При переносе на другой компьютер рабочее окружение Python может потребовать отдельного восстановления; простое копирование `venv` не гарантирует переносимости.

**Страница не открывается:** проверьте, запущен ли START_HEXW.cmd и не закрыто ли окно сервера. **Адрес занят:** возможно, уже работает другая копия; не закрывайте неизвестные процессы. **Показан старый интерфейс:** после перезапуска обновите вкладку. **Результаты после перезапуска не исчезают:** они хранятся на диске. **График не попал в диапазон:** проверьте CSV, статус пика, частотную сетку и интервалы; увеличивайте диапазон по обоснованной задаче. **Слишком широкая полоса:** сначала уточняйте физические параметры и применимость, а не выдавайте увеличение числа сценариев за улучшение научной точности.

## Команды для коллеги или ИИ-агента

В подготовленной среде можно работать без интерфейса. Пример PowerShell:

```powershell
$env:HEXW_ROOT='C:\MIPT\working_stuff\Hexx'
Set-Location -LiteralPath 'C:\MIPT\working_stuff\Hexx\project'
& '..\tools\venv\Scripts\python.exe' -B -m hexw predict --config config/cozn_first_example.yaml
```

Для продолжения используйте `python -m hexw resume --run <полная папка прогноза>` в этой же рабочей среде. Фиксация — `python -m hexw freeze-model --run <папка прогноза>`. Это дополнительные способы; для обычной работы достаточно интерфейса.
