# Совместная работа

1. Примите приглашение в приватный репозиторий. Клонируйте его с Git LFS, выполните установку из README.
2. Перед новой задачей обновите основную ветку и создайте отдельную ветку.
3. Внесите изменения, выполните подходящие проверки, сделайте коммит и отправьте ветку.
4. На GitHub нажмите **Compare & pull request** и опишите изменение и проверки. Второй участник просматривает правки; затем их объединяют в `main`.
5. После объединения обновите свою `main`. Не редактируйте одну сетевую папку вдвоём и не применяйте force push к общей ветке.

Пример (имя ветки замените своим):

```powershell
git switch main
git pull --ff-only
git lfs pull
git switch -c codex/my-change
# Отредактируйте нужные файлы.
git add project/hexw/имя_файла.py
git commit -m "Describe the change"
git push -u origin codex/my-change
```

Можно использовать GitHub Desktop. Небольшие текстовые правки также доступны в редакторе GitHub: выбирайте новую ветку и Pull Request. Большие файлы обрабатывайте локально с Git LFS.

## Проверки

Из корня клона:

```powershell
cd project
..\tools\venv\Scripts\python.exe -m pytest tests/test_ui.py -q
```

Полный обычный прогон требует времени; он нужен при изменении расчётной части или перед выпуском:

```powershell
..\tools\venv\Scripts\python.exe -m pytest -m "not slow and not dft" -q
```

## Новые данные и результаты

Первоначальные результаты уже отслеживаются. Новые файлы в `runs/` и `vault/` по умолчанию игнорируются. Выбранный новый результат публикуйте явно:

```powershell
git add -f runs/predictions/НОМЕР_НОВОГО_РАСЧЁТА
```

Проверьте, что не попали ключи или личные данные. Не переписывайте прежние результаты; новый расчёт публикуйте отдельно. Теория использует литературный FIT-корпус, лабораторные данные служат для проверки. При изменении кода, литературы или среды нужен новый прогноз и фиксация перед сравнением.

`registry/FROZEN_MODEL.json` первоначально опубликован явно, несмотря на локальный `.gitignore`. Не заменяйте его случайно; новую фиксацию добавляйте отдельным Pull Request вместе с её прогнозом.

Приглашение участников и принудительная защита `main` требуют прав владельца. В этой публикации защита не настроена; рекомендуется взаимный просмотр Pull Request.
