# DFT-адаптер Quantum ESPRESSO (hexw.dft): обменные константы J из коллинеарных конфигураций

Этап 5. Собственные коллинеарные расчёты DFT+U дополняют литературу: в fit-корпусе нет обменов J_ij для W-фазы (статья Islam 2024 PRB
недоступна), для Mn в Sr-W литературы нет вообще. Модуль строит набор магнитных конфигураций упорядоченной структуры, готовит и валидирует
входы `pw.x`, запускает их очередью с контрольными точками, разбирает вывод, проверяет, что конфигурация сохранилась, и по энергиям находит J
методом наименьших квадратов с проверкой на отложенных конфигурациях (ТЗ §8.8). Результат — `ParameterEstimate` с `source_role=dft`.

Границы: энергии при 0 K, коллинеарно, без релаксации (геометрия — CIF L02 через `generate_configurations`), псевдопотенциалы и обрезание
пилотные. Энергии **не** превращаются в фазовые доли (ТЗ §8). Полная W-кампания в этом этапе **не запускалась**: есть планы, сгенерированные и
провалидированные входы; запуск — `hexw dft run --i-accept-runtime`. Лабораторные данные на выбор настроек не влияли.

**Версия настроек: `campaign_v2`** (после независимого ревью, круг 1; `config/dft/campaign_v2.yaml`, новый хэш = новая версия; `campaign_v1.yaml` сохранён без
изменений, по нему записан smoke на гематите §9). Что изменилось относительно v1: проектор `atomic` + `K_POINTS gamma` (§1.1), `electron_maxstep` 100,
порог шума 10 мэВ и относительный критерий отложенных (§8), локализация Fe²⁺ и контроль валентности (§5, §7), нуисанс-столбцы дальних пар (§3, §8).
Тест k-точек `config/dft/ktest_v1.yaml` (кампания `ktest_v1`) — §12.

Модули: `settings` (конфиг, хэш, профили псевдопотенциалов), `hamiltonian` (конвенция, матрица плана, МНК), `magnet` (связи, классы J, выбор
конфигураций), `qe_input` (входы и валидация), `parse` (разбор `pw.out`, проверка конфигурации), `runner` (очередь, статусы, журнал),
`campaign` (plan/generate/collect/fit-j, `ParameterEstimate`, `RunManifest`), `soc` (неколлинеарные входы, запуск запрещён), `hematite`
(smoke-система), `cli`; вспомогательные `hexw.util.keepawake`, `hexw.util.proc`. Конфиг: `config/dft/campaign_v2.yaml`. Тесты: `tests/dft`.

### 1.1 Решение по проектору (тест на гематите, 2×2×2, 40/240 Ry, 10 атомов, 1 процесс на расчёт)

Критерий (задан заранее): если fit-запись L05 указывает проектор — берём его; иначе, если |ΔE_ortho − ΔE_atomic| / |ΔE| < 5 %, берём `atomic` + `K_POINTS gamma`; иначе `ortho-atomic`. **L05 проектор не указывает**: в `hexw.params.literature` у записей L05-001…L05-119 (метод и примечания) нет слов projector / orthogonal / Löwdin; L05 — VASP (проекция на сферы). Значит решает число.

ΔE = E(3:1) − E(АФМ), 3:1 = конфигурация с перевёрнутым одним Fe (`c04_flip_Fe4`), АФМ = `c00_ground` (+−−+), энергии `!` из `pw.out`:

| проектор | E(АФМ), Ry | E(3:1), Ry | ΔE, мэВ | итераций | CPU на расчёт |
|---|---|---|---|---|---|
| `ortho-atomic` (прогон smoke v1, `dft_runs/campaign_v1/hematite_alpha-Fe2O3`) | −1194.89796447 | −1194.84882913 | **668.52** | 12 / 12 | 65–80 с |
| `atomic` (`dft_runs/projtest_hematite/atomic`) | −1194.85413260 | −1194.80255234 | **701.79** | 12 / 12 | 87–91 с (2 процесса одновременно) |

|ΔE_ortho − ΔE_atomic| = 33.27 мэВ → **4.98 %** от ΔE_ortho (4.74 % от ΔE_atomic, 4.86 % от среднего) < 5 % → выбран `atomic` + `K_POINTS gamma`. **Оговорка:** запас до порога 0.02 процентного пункта; правило применено механически, это не доказательство близости проекторов. Абсолютные энергии разных проекторов несравнимы (различается энергия Хаббарда), сравниваются только разности. Один расчёт пары, без перебора U и k.

Проверка Γ-трюка на гематите (`atomic`, Γ, один и тот же вход): `K_POINTS automatic 1 1 1` против `K_POINTS gamma` — энергия −1194.84070467 против −1194.84070468 Ry (совпадает до 1e-8 Ry), wall 24.8 → 14.7 с (**×1.69**), оценка RAM QE 197 → 109 МБ (**0.55×**). С `ortho-atomic` и `K_POINTS gamma` QE 7.6 останавливается: `Error in routine orthoUwfc: Gamma-only calculation for this case not implemented`; код (`qe_input`, `settings`) отказывает в такой комбинации.

Проверка `starting_ns_eigenvalue` в QE 7.6 (гематита, Γ, `atomic`, `tot_charge=-1`, один атом Fe отдельным видом с `starting_ns_eigenvalue(5,2,3)=1.0`): ключ **принят**, QE печатает `WARNING!!! Modifying starting ns matrices according to input values` и пересчитывает занятость (Tr[ns] down атома 1 на втором шаге 1.29 против 0.57 в нейтральном прогоне без ключа — прогоны различаются зарядом, это не чистое сравнение), SCF сошёлся за 19 итераций. **К концу SCF электрон распределился по всем четырём Fe** (Tr[ns] total 6.19 / 6.31 / 6.19 / 6.31): ключ только задаёт начальное приближение и локализацию не гарантирует — поэтому после расчёта проверяется положение Fe²⁺ (§7). С `ortho-atomic` ключ не проверялся (Γ-вход с ним невозможен, а выбран `atomic`).

## 2. Конвенция гамильтониана

```
H = − Σ_{i<j} J_ij  S_i · S_j
```

* каждая пара один раз; пара атома с периодическим образом партнёра — отдельная связь; пара атома с собственным образом постоянна во всех
  коллинеарных конфигурациях и уходит в E0;
* S_i — **векторы длины |S|** (спиновое квантовое число): Fe³⁺ 5/2, Fe²⁺ 2, Mn²⁺ 5/2, Mn³⁺ 2, Co²⁺ 3/2, Ni²⁺ 1, Zn/Mg 0 (`hamiltonian.SPIN_S`).
  Выбор |S| (а не единичных векторов) делает J одного типа связи сравнимым между составами и ионами;
* **J > 0 — ферромагнетизм**, J < 0 — антиферромагнетизм;
* единицы: **мэВ**, энергии — на ячейку моделирования (1 Ry = 13605.693123 мэВ).

Коллинеарная конфигурация с знаками σ_i = ±1: `E_c = E0 + Σ_g J_g X_{c,g}`, `X_{c,g} = − Σ_{связи b ∈ g} S_i S_j σ_i σ_j`.

Перевод в другие конвенции: `hamiltonian.convert_J(J, S_i, S_j, src, dst)`; `Convention(sign, counting, spin)`: `sign=+1` — `H=+Σ…`
(J>0 антиферро), `counting='twice'` — сумма по i≠j (J вдвое меньше), `spin='unit'` — единичные векторы (`J_unit = J·S_i·S_j`).
Энергия пары во всех конвенциях совпадает (тест).

## 3. Пары обмена и классы J (W-фаза, 92 атома)

Связи — пары магнитных катионов (S>0) ближе `r_cut = 3.8 Å` (расстояния Fe–Fe 2.7–3.8 Å: общая грань, общее ребро, общий угол полиэдров),
со всеми периодическими образами; для каждой считаются число общих атомов O (путь сверхобмена: грань 3, ребро 2, угол 1, 0 — нет общего O) и угол
Fe–O–Fe для угловых путей.

**Что определяется.** Единица переворота — подрешётка W1…W7 целиком. Тогда σ_iσ_j меняется только для пар разных подрешёток, и из энергий
определяется один J на пару подрешёток (`group_by: sublattice_pair`); внутриподрешёточные связи (W1–W1, W3–W3, W5–W5, W6–W6) неотличимы от E0 — для них
понадобились бы переворот отдельных позиций и суперъячейка (на 92 атомах нереально, FEASIBILITY §3). J класса — среднее по связям класса
(при нескольких расстояниях внутри пары подрешёток — взвешенное по вкладу в конфигурации). Классы с **пропорциональными** столбцами (физически
неразличимы никаким набором переворотов) сливаются автоматически; определяется комбинация `J_master + Σ r·J_member` (в W-фазе слияний нет, в
гематите — есть, см. §9).

**Что такое J класса (эффективный J).** Для пары подрешёток a–b все связи между ними (любой длины, включая дальше 3.8 Å) имеют одно и то же σ_iσ_j во всех
перевёртах подрешёток, поэтому их вклад в энергию пропорционален одному столбцу. Определяемая величина —

    J_класса(a–b) = Σ_{все пары i∈a, j∈b} J_ij S_i S_j / Σ_{связи a–b короче 3.8 Å} S_i S_j,   (для равных спинов: Σ J_ij S_i S_j / (число близких связей × S²))

— **эффективный J спиновой модели на тех же близких связях** (учитывает вклад далёких пар этой же пары подрешёток точно; проверено тестом
`test_effective_j_of_a_class_absorbs_all_pairs_of_the_two_sublattices` случайными J всех связей до 8 Å). Это не «J ближайшего соседа»: числа нельзя сравнивать с
J ближайших связей из других работ без этой оговорки.

**Пары подрешёток без близких связей** (нет связи короче 3.8 Å, но есть дальше, до 8 Å): W3–W5, W4–W6, W1–W6, W1–W7, W2–W7, W3–W6, W4–W7. Их J не определяются
(классов нет), а энергия этих пар перевёртами подрешёток **алиасится** на 13 определяемых J. Для них в фит добавляются **нуисанс-столбцы** (по одному на пару,
столбец = −Σ по дальним связям S_iS_jσ_iσ_j, `design.json: X_far`) с гауссовым приором **σ = 0.1 мэВ на связь — допущение (ASSUMPTION)**, `exchange.far_prior_sigma_meV`;
σ(J) вычисляется как маргинал совместного апостериорного распределения (§8), т. е. честно включает алиасинг (методика MC ревьюера, `hexw.dft.hamiltonian.fit_exchange`).
Число связей: W3–W5 156 (5.26–7.93 Å), W4–W6 24 (5.55–7.88 Å), W1–W6 12 (6.05), W1–W7 12 (7.21), W2–W7 12 (6.15), W3–W6 12 (7.06), W4–W7 4 (5.74 Å) в ячейке.

**Неопределяемые внутриподрешёточные J:** W1–W1, W3–W3, W5–W5, W6–W6 (связи короче 3.8 Å внутри одной подрешётки; σ_iσ_j = +1 при любом перевороте подрешётки →

## 4. Выбор конфигураций и обусловленность

Пул — все 2⁶ = 64 переворота подрешёток относительно основного состояния Гортера (W3, W4, W5, W7 вверх; W1, W2, W6 вниз; `hexw.params.moments` /
`structures.sites`), глобальный переворот эквивалентен. Подбор: жадный D-оптимальный отбор (по логарифму определителя нормированной матрицы
`[1, X]`), затем обмен конфигураций, минимизирующий число обусловленности; основное состояние всегда первое. Одинаковые строки матрицы (эквивалентные
по модели и обычно по симметрии кристалла конфигурации) не запускаются дважды и не могут быть отложенной проверкой (для отложенной нужна строка, которой
нет в фите; иначе `DesignError`).

* fit: `n_J + 1 + n_extra_fit` (n_extra_fit = 1 → запас по степеням свободы dof = 1);
* отложенные: `n_holdout = 2`, максимизируют минимальное расстояние Хэмминга до fit-набора (ТЗ §8.8, они не входят в фит).

Для SrFe18O27 и для SrFe16Mn2O27 (Mn²⁺, `Hypothesis(mn_valence=2)`): 13 J + E0 → **15 fit + 2 отложенных = 17 расчётов** (чуть выше ориентира
12–16: N_J = 13). Число обусловленности нормированной матрицы fit-набора **2.45** (весь пул из 64: 1.0 — разные характеры группы ортогональны),
ранг 14/14; сингулярные числа (нормированные): 1.349, 1.321, 1.294, 1.189, 1.033 (×5), 0.779, 0.648, 0.607, 0.559, 0.552;
без нормировки cond = 177 (SrFe18O27) / 192 (Mn). Плечи (leverage) отложенных: 1.68 и 2.11.
Конфигурации (переворачиваемые подрешётки): c00 ground; c01 W3 W4 W5 W6 W7; c02 W2 W5 W6; c03 W3 W5 W7; c04 W2 W4 W5 W7; c05 W4 W5; c06 W2 W3 W6;
c07 W4 W6; c08 W2 W4; c09 W2 W3 W4 W6 W7; c10 W5 W6; c11 W2 W3 W5; c12 W2 W6 W7; c13 W3 W6 W7; c14 W3 W7 | отложенные: c15 W4 W7; c16 W3 W4.

Состав влияет на план только через длины спинов и магнитные атомы; геометрия — одна и та же CIF L02, поэтому **набор конфигураций, знаковая структура и
обусловленность (нормированная) совпадают, но матрицы X для Mn- и Fe-состава НЕ совпадают**: столбец класса равен −W_g σ_aσ_b с весом W_g = Σ S_iS_j по связям
класса, а у Fe-состава 4 атома Fe²⁺ (S=2), у Mn-состава 4 атома Mn²⁺ (S=5/2), и веса различаются (проверено по `design.json` обоих составов: максимум |ΔX| = 15 при
масштабе 150, до 10 % в отдельных классах; число обусловленности нормированной матрицы одинаково, 2.4457, потому что нормировка столбцов убирает веса). Утверждение
«матрицы совпадают» в первой редакции было неверным; J двух составов надо подгонять по их собственным X. **Допущение:** один J на класс независимо от сорта пары (Fe–Fe, Fe–Mn, Fe²⁺–Fe³⁺); спиновые длины входят
в коэффициенты явно, остаток смешанных пар проявится на отложенных конфигурациях. Положение Fe²⁺ — **одна заглушечная реализация** (`generate_configurations`: размещение «наибольшего взаимного расстояния», не перебор ансамбля; §5).

## 5. Входы pw.x

Для каждой конфигурации `build_input` пишет `pw.in`: разные виды (species) для разной ориентации — `Fe1` (вверх) / `Fe2` (вниз), `Mn1/Mn2`, `Co1/Co2`
(метки QE ≤ 3 символов), `starting_magnetization` со знаком целевой конфигурации, немагнитные `Sr`, `O`, `Zn` — с нулевым моментом, `HUBBARD
{atomic}` с `U Fe1-3d 3` и т. д. (не для Zn). Заголовок содержит хэш конфига.

**Локализация Fe²⁺ (режим `dft.fe2_localization.mode: seeded`).** Ионы Fe²⁺ (степень окисления 2 в упорядоченной структуре) получают собственные виды: **`Fe3` — Fe²⁺ спином вверх,
`Fe4` — Fe²⁺ спином вниз** (в постановке задания «Fe2p_up / Fe2p_dn»; метка QE ≤ 3 символов), с собственным `starting_magnetization` (0.32 = 0.4 × 4/5, допущение; знак по
целевой конфигурации), `U` как у Fe и **`starting_ns_eigenvalue(m, ispin, ityp)`** в `&SYSTEM`: пятое (старшее) собственное значение матрицы заселённости **миноритарного**
спинового канала вида равно 1 (d⁶ = d⁵ + один электрон в миноритарном канале; для вида «вверх» `ispin=2`, для «вниз» `ispin=1`). Проверено на QE 7.6 с проектором `atomic`
(§1.1): ключ принят и применён; с `ortho-atomic` не проверялся. Если бы ключ не поддерживался, оставались бы только виды + `starting_magnetization` (режим `use: false`).
Режим `none` — Fe²⁺ как обычное Fe (начальное приближение без подсказки о положении электрона; **второй старт** k-теста, §12).

**Расположение Fe²⁺ берётся из `generate_configurations`** (`hexw.structures.configs`), где оно сейчас — **одна заглушечная реализация** (размещение «наибольшего взаимного
расстояния» в выбранном сценарии, не перебор и не ансамбль). Энергии и J относятся к этому одному расположению; зависимость J от расположения Fe²⁺ не исследована.
Локализация только задаёт начальное приближение; факт сохранения проверяется после расчёта (§7).

`validate_input` (вызывается при генерации, любая проблема — ошибка): набор namelist, `nat`/`ntyp` против карточек, метки ≤ 3 символов, все виды
использованы и объявлены, псевдопотенциал существует, соответствует элементу и профилю, обрезания не ниже профиля и `ecutrho ≥ 4·ecutwfc`,
`starting_magnetization` в [−1, 1] и знак по атомам совпадает с целевой конфигурацией (у немагнитных нулевой), `tot_magnetization` не задан (если
конфиг не фиксирует), U соответствуют конфигу (нет U у Zn), проектор совпадает, нет атомов ближе 1 Å, целое число электронов, нет `noncolin`/`lspinorb`,
`calculation='scf'`. Тесты: `tests/dft/test_dft_qe_input.py` (в том числе все 17 входов SrFe18O27 и SrFe16Mn2O27).

## 6. Запуск и оркестрация

* Программы запускаются **только** через `hexw.util.external.run_external` (белый список). В список добавлен `pw_big.exe` (точечная правка
  `hexw/util/external.py`, строка в `docs/ISOLATION.md`): `pw.exe` собран с малым стеком и падает по переполнению даже на 10-атомной ячейке
  (код 0xC00000FD), `pw_big.exe` — та же сборка с увеличенным стеком (`tools/patch_stack.py`). `pw.x` читает вход со stdin (`stdin_path`).
* **Поток вывода.** `run_external(..., stdout_path=, stderr_path=, pid_callback=)`: `pw.x` пишет в `pw.out` / `pw.err` **прямо во время расчёта** (без `capture_output`,
  без накопления в памяти; ход виден по `pw.out`, файл переживает падение запускающего процесса); запуск без shell, белый список прежний; PID дочернего процесса пишется в
  `status.json` (`pw_pid`). Тесты: `tests/test_subprocess_policy.py`, `tests/dft/test_dft_runner.py`.
* **Keep-awake.** `hexw.util.keepawake.keep_awake()` — `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)` через ctypes/kernel32 на время `run_queue` (на потоке очереди, он
  живёт всё время; флаг привязан к потоку); по выходу сбрасывается `ES_CONTINUOUS`. Экран может гаснуть (`ES_DISPLAY_REQUIRED` не задан). Настройки питания (`powercfg`) **не
  меняются**. **Ограничение: закрытие крышки ноутбука (действие по умолчанию — сон) или кнопка питания всё равно усыпляют машину и останавливают расчёт**; для длинного
  прогона крышка должна быть открыта. В журнал пишется событие `keep_awake` (`active`, `error`). Функция не читает файлов и не запускает процессов.
* **Осиротевшие задачи.** Перед перезапуском задачи в состоянии `running` с устаревшим heartbeat проверяется, жив ли процесс с записанным `runner_pid` или `pw_pid` (Windows:
  `OpenProcess` + `GetExitCodeProcess`, не `os.kill`: на Windows он завершает процесс). Если жив — задача **не перезапускается**, статус `orphan_running` (даже с `--force`; heartbeat
  устаревает и при сне ноутбука, а два писателя в одном каталоге испортят расчёт). PID, переиспользованный системой, выглядит живым — безопасная сторона; тогда удалить `status.json`.
* Каталог: `<HEXW_ROOT>/dft_runs/<campaign>/<composition>/<config_id>/` (вне project): `pw.in`, `job.json`, `status.json`, `pw.out`, `result.json`;
  на уровне состава `design.json`, `plan.json`, `manifest.json` (`RunManifest`, хэши входов и псевдопотенциалов, версии), `journal.jsonl`,
  `collected.json`, `fit_j.json`, `estimates.json`, `soc/`.
* Очередь: до N процессов (потоки Python вокруг `run_external`; по умолчанию 3, не больше `engine.max_parallel`, проверка памяти 3.3 ГБ × N ≤
  `memory_budget_GB` = 10 ГБ), 1 OpenMP-поток. Таймаут на задачу (12 ч для 92 атомов).
* Статусы: `pending → running → done | failed | timeout | not_converged`; `orphan_running` (выше); `input_changed` (завершённый расчёт, вход которого потом изменили, молча не
  перезапускается), `not_feasible_on_laptop` (SOC, никогда не запускается). **Resume:** `done` не трогается; `running` со свежим heartbeat (30 с;
  `stale_after_s` = 180 с) принадлежит другому запуску и пропускается, с устаревшим — перезапускается с нуля (у частично пройденного `pw.x` нет
  пригодного рестарта); `failed/timeout/not_converged` — только с `--retry-failed`. Запись статуса атомарна (`os.replace`, повтор при блокировке на Windows).
* Перед массивом: оценка по FEASIBILITY (`seconds_per_scf_iteration × scf_iterations`: 290 с × 40 итераций = 3.2 ч CPU на конфигурацию; 3 процесса
  с коэффициентом замедления 1.2 — допущение, из пилота a), печатается и при превышении порога `confirm_above_cpu_hours` (0.25 ч) команда `run`
  **отказывает** без `--i-accept-runtime` (код 2, ничего не запущено).
* Журнал `journal.jsonl` (JSON-строки: generate, queue, start, finish, collect, interrupted).

## 7. Разбор вывода и контроль конфигурации и валентности

`parse.parse_pw_output`: версия QE, сходимость и число итераций, полная энергия (`!`, только при сходимости; несошедшаяся энергия не результат),
вклад сглаживания, оценка точности SCF, полная и абсолютная намагниченность, моменты на атомах («Magnetic moment per site», интегрирование на сфере),
**полная `Tr[ns]` (up, down, total) по атомам** (последний шаг SCF и первый блок — начальные заселённости) и суммарная намагниченность, d-моменты из `Tr[ns]` для атомов с U, число k-точек/электронов, CPU/WALL, **оценка** RAM из вывода QE (пик памяти процесса не измеряется), ошибки.

`check_configuration`: для каждого магнитного атома знак момента должен совпасть с целевым и `|m| ≥ 0.5·2S` (сферический момент ≈ 0.8 ионного). Иначе
конфигурация помечается **`config_not_preserved`** (перевернувшиеся/схлопнувшиеся атомы указаны) и в фит не идёт; без моментов на атомах конфигурацию
проверить нельзя — тоже не идёт. Не сошедшиеся, упавшие и просроченные расчёты в фит не идут.

**Контроль валентности** (`parse.check_valence`, вызывается из `collect`; пороги `valence_check` в конфиге). Электрон Fe²⁺ в коллинеарном DFT+U может уйти на другой атом Fe или
размазаться; энергия при этом меняется на десятки мэВ — сильнее обменов. Статусы (в фит идёт только `ok`):

* **`valence_changed`** — (а) множество Fe с **наибольшей заселённостью d (Tr[ns] total)** (при отсутствии Tr[ns] — с наименьшим |m|) не совпадает с заданным расположением Fe²⁺;
  (б) |M_tot − M_ожид| > 0.5 μB, M_ожид = Σ sign·2S по магнитным атомам; (г) для Mn-состава (Mn²⁺): сферический момент Mn < 0.9 × средний момент Fe³⁺ (Mn³⁺ d⁴ дал бы
  ≈ 0.8; 0.9 — **допущение**, не калибровано);
* **`smearing_large`** — |TS| (вклад smearing) ≥ 1 мэВ: дробные заселённости на уровне Ферми, изолятор не сохранился;
* `not_converged` (100 шагов исчерпаны), `config_not_preserved` (знак/схлопывание момента) — как раньше.

В строку результата пишутся `valence_check` (найденные и заданные Fe²⁺, `nd_gap` — зазор Tr[ns] между Fe²⁺ и остальными Fe, M_ожид, M_tot, TS), `hubbard_ns`, `hubbard_ns_start`.
Порог (б) 0.5 μB и сам критерий (а) **не калибровались на W-ячейке**: первые данные дадут k-тест (§12); возможны ложные срабатывания, если Fe в тетраэдрах и октаэдрах
имеют разную заселённость d (тогда критерий нужно менять по данным, не ослаблять наугад).

## 8. Фит и отложенные конфигурации

`hamiltonian.fit_exchange`: МНК `E = E0 + X·J`; ковариация `σ²(AᵀA)⁻¹`, `σ = max(√(RSS/dof), floor)`, где floor = `energy_noise_floor_meV` = **10 мэВ** (v1: 0.5 мэВ) —
**допущение, но с эмпирическим основанием:** ошибка самой модели Гейзенберга на отложенной конфигурации гематиты составила **7.3 мэВ** (§9, при размахе 1.43 эВ), то есть на порядок
выше любого шума SCF/Γ (0.5 мэВ); пол ниже ошибки модели делал бы σ(J) заведомо заниженными. 10 мэВ = 7.3 мэВ, округлённое вверх; это не подгонка под проверку, а масштаб
ошибки модели, измеренный на единственном доступном примере (его переносимость на W-фазу не доказана). При dof = 0 фит точный и неопределённость только от floor (помечено в `notes`).
Остатки, leave-one-out, число обусловленности и SVD.

**Нуисанс-столбцы дальних пар (§3).** `E = E0 + X·J + X_far·g`, `g ~ N(0, (0.1 мэВ)²)` (допущение). Оценка — апостериорное среднее, ковариация [E0, J] — маргинал совместной апостериорной
ковариации `σ²(BᵀB + diag(0, σ²/τ²))⁻¹`, `B = [1, X, X_far]` (σ в штрафе — неподвижная точка с итоговым σ). dof остаётся n − p: нуисанс-параметры стянуты приором и как подгоняемые не
считаются. В `fit_j.json: nuisance` — апостериорные среднее и σ дальних пар, σ(J) без нуисанс и **коэффициенты раздувания** σ.

**Критерий отложенных конфигураций — относительный:** `rms(ошибки на отложенных) / (размах энергий fit-набора) < 2 %` (`exchange.holdout_rel_tol`, допущение). z-критерий против шума
0.5 мэВ отвергнут: он браковал даже 0.5 % ошибки модели на гематите (z = −13). Если критерий не выполнен — `holdout_consistent=false`, rms ошибки добавляется в квадратуре к σ
(`sigma_J_total`; нижняя граница ошибки модели, не её оценка) и **`identifiable=false`**, `Uncertainty.kind = unknown` у каждой оценки `dft_J_*` (раньше флаг зависел только от
обусловленности). Без отложенных (`holdout_consistent=None`) `identifiable` определяется обусловленностью, а в провенансе стоит `holdout_check` с причиной.

**Потеря fit-конфигураций.** Если потеряно **1–2** запланированные fit-конфигурации (`valence_changed`, `not_converged`, `failed` …), завершившиеся отложенные конфигурации **продвигаются в
fit** (`holdout_promoted_to_fit`), проверка отложенных **недоступна** (`holdout_check: unavailable…`, `holdout=null`, `holdout_consistent=null`; запись в провенанс каждой оценки: модель не
проверена на независимых конфигурациях). Потеряно > 2 — фит `incomplete`, ничего не публикуется. Продвигаются все завершившиеся отложенные (проверка всё равно недоступна).

`ParameterEstimate`: имя `dft_J_<класс>`, единица мэВ, `source_role=dft`, `quantity_kind=energy`; `Provenance.note` — JSON: хэш конфига, хэш
входов+выходов, версия QE, `cutoff_status`, статусы U, `holdout_consistent`, `holdout_check`, `holdout_promoted_to_fit`, нуисанс-столбцы, смысл J (эффективный, §3), температура/ограничения.
`identifiable=false` и `kind=unknown`, если число обусловленности выше порога или `holdout_consistent=false`.

## 9. Smoke-тест на α-Fe2O3 (реальный pw.x)

Геометрия: R-3c, a = 5.038 Å, c = 13.772 Å, Fe z = 0.3553, O x = 0.3059 (Blake et al. 1966, через `dft_feasibility/pilots/make_a.py`; пилот a не
является производным holdout — CIF не читается; числа в этом запуске по статье не перепроверялись), примитивная ячейка 10 атомов, 4 Fe,
основное состояние +−−+ вдоль тригональной оси. Флипы — отдельные атомы Fe; `r_cut = 3.8 Å`, классы по оболочкам. 4 Fe → 5 различных строк
матрицы: оболочки 2.90 Å (грань) и 3.36 Å (угол) соединяют одни и те же пары атомов (столбцы пропорциональны, ×3) и сливаются: фит определяет
`J(2.90) + 3·J(3.36)`; J(2.97, ребро) и J(3.71, угол). 3 J + E0 = 4 параметра = 4 fit-строки (dof 0), пятая строка — отложенная.
Попытка модели без оболочки 3.71 Å не описывает данные (остаток ~400 мэВ при размахе 1.4 эВ).

Запуск: `HEXW_RUN_DFT=1 python -m pytest tests/dft/test_dft_smoke_hematite.py -m dft -s` (не входит в обычный pytest). 5 конфигураций, 3 процесса, 2 мин 22 с wall
(54–80 с на расчёт, 11–12 итераций), пик памяти QE ≈ 0.2 ГБ. Результат (кампания `campaign_v1`, `dft_runs/campaign_v1/hematite_alpha-Fe2O3`):

| класс | J, мэВ (только фит → с ошибкой модели) |
|---|---|
| J(2.90 Å грань) + 3·J(3.36 Å угол) | −25.82 ± 0.02 → ± 0.29 |
| J(2.97 Å ребро) | −1.05 ± 0.01 → ± 0.10 |
| J(3.71 Å угол, Fe–O–Fe 132°) | −5.23 ± 0.00 → ± 0.05 |

Знаки: все J отрицательны (антиферро), основное состояние +−−+ — самое низкое по DFT-энергии из пяти (на 0.67 эВ ниже конфигураций 3:1), полный момент 0,
моменты на сфере Fe ≈ 3.8 μB. Отложенная конфигурация (3:1, строка X = 0, предсказание = E0): **ошибка −7.3 мэВ при размахе энергий 1.43 эВ (0.5 %)**, но
σ предсказания 0.56 мэВ, **z = −13**: Гейзенберг-модель из трёх классов не доказывает точность на уровне шума floor; поэтому неопределённости
увеличены ошибкой модели, а J — лишь согласованные по знаку и порядку величины (десятки мэВ в соглашении |S|) значения для проверки цепочки,
не результат о гематите (пилотные обрезания, 4-атомная ячейка, U = 3 эВ). (Под v2 критерий отложенных относительный: 7.3 / 1430 = 0.5 % < 2 % — согласованно; z = −13 относится к критерию v1.) Записанные ранее «предварительные» прогоны (`prelim_hematite_*_superseded`) — отброшенные
варианты плана (дублирующие строки, 2-J модель); в выводы не входят.

### 12.1 Решающий тест k-точек на W-ячейке (`ktest_v1`)

Вопрос: допустим ли Γ (вместо Γ-центрированной сетки L05 5×5×1) для разностей энергий конфигураций? Ревьюер показал на гематите, что ошибка по k не зависит от обрезания в пределах 1 мэВ,

(почти ферромагнитная: все подрешётки смотрят в одну сторону, кроме W6; обратный знак всего — та же конфигурация). Пять расчётов (`hexw dft ... --config config/dft/ktest_v1.yaml`, каталог `D:\Work\Hexx\dft_runs\ktest_v1\`):

| расчёт | каталог (`--tag`) | k-сетка | старт Fe²⁺ |
|---|---|---|---|
| c00, c01 | `SrFe18O27_uniform_cfg0_g` (`g`) | `K_POINTS gamma` (`--kpoints 1,1,1`) | seeded |
| c00, c01 | `SrFe18O27_uniform_cfg0_k221` (`k221`) | automatic 2 2 1 (`--kpoints 2,2,1`) | seeded |
| c00 (второй старт) | `SrFe18O27_uniform_cfg0_g_alt` (`g_alt`) | `K_POINTS gamma` | `none` (`--fe2-start none`: Fe²⁺ как обычное Fe, без вида и без `starting_ns_eigenvalue`) |

**Критерии решения (записаны до получения результатов).** ΔE_k = E(c01) − E(c00) при данной сетке:

* |ΔE_Γ − ΔE_2×2×1| / |ΔE_2×2×1| ≤ **10 %** → Γ допустим, систематика ±10 % на J;
* **10–30 %** → Γ с поправочным множителем ΔE_2×2×1/ΔE_Γ и систематикой (разброс множителя — по этому единственному сравнению, это грубо);
* **> 30 %** → кампания на 2×2×1 (≈ 3.8× дороже Γ с трюком, оценка 5 ч против 1.3 ч на расчёт) или сокращённая (меньше классов J / меньше конфигураций);
* расхождение двух стартов c00 (seeded и none) на Γ **> 10 мэВ** → без фиксации положения Fe²⁺ кампания бессмысленна, нужна стратегия фиксации (например, ограничение заселённости,
  `tot_magnetization`-ограничения по подрешёткам или перебор положений); ≤ 10 мэВ → старт не влияет на энергию в пределах порога.

Перед использованием результатов выполнить `collect` (контроль валентности §7 и `config_not_preserved`): расчёт со статусом не `ok` для решения не годится (кроме второго старта: у него
`valence_changed` — тоже информация, и сравнивается энергия `energy_meV` как есть). Результаты: см. раздел «Результаты k-теста» ниже (заполняется после завершения).

## 13. Допущения и ограничения (сводка)

* U(Co), U(Mn) = 3 эВ — assumption; анализ чувствительности к U, псевдопотенциалу и обрезаниям (ТЗ §8.5, §8.4) не сделан; обрезания пилотные.
* Γ-только вместо 5×5×1 (допустимость решает §12); без релаксации; 0 K; без орбитального вклада.
* Один J на пару подрешёток (или оболочку) независимо от сорта пары; J — эффективный (§3); внутриподрешёточные J не определяются; обрезание близких связей 3.8 Å; приор дальних пар 0.1 мэВ — допущение.
* floor 10 мэВ — допущение с основанием (7.3 мэВ на гематите); при dof = 1 оценка σ из остатка груба; отложенные конфигурации — главная проверка модели (при потере ≤ 2 fit-конфигураций недоступна, §8); порог 2 % — допущение.
* Контроль валентности (пороги 0.5 μB, 1 мэВ, 0.9) не калиброван на W-ячейке; `atomic` выбран по запасу 0.02 п. п. (§1.1).
* Закрытие крышки ноутбука усыпляет машину, keep-awake этого не отменяет (§6).
* Fe²⁺ размещён одной заглушкой (`generate_configurations`), в планах Fe²⁺ отличается спином 2 в коэффициентах; локализация — только начальное приближение (§5).
* Память процесса — оценка QE, не измерение; время — оценка по пилотам, не по этой задаче.
